# GitOps release verification

Follow the user's requested release path once the work is ready. Reuse existing checks and inspect the actual merge, package or deployment result as appropriate; distinguish merged code from a verified deployed revision. Verify the exact revision where concurrent changes matter.

Preserve unrelated work and existing security and recovery boundaries. Investigate actual failures and material applicable risks; do not add new validation campaigns or approval steps when the user has already authorized the next action. Report unfinished prerequisites and uncertainty without silently narrowing the requested delivery.
