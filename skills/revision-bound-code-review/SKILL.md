# Revision-bound code review

Read the relevant change and its consumer path at the revision being reviewed. A blocking finding needs a concrete failure of the requested behavior, an observed defect or a material applicable risk, with the trigger, consequence and smallest useful correction. Label a plausible but unestablished concern as a question or non-blocking risk; do not convert it into a release gate by default.

Use existing evidence and choose checks proportionate to the change. Do not repeat a completed check without a new reason or demand a campaign of edge cases unrelated to the work. If new evidence or user steering changes the task, update the plan and proceed toward the current requested outcome. Report limits accurately without changing the outcome being claimed.
