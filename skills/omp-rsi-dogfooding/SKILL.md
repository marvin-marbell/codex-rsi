# Codex RSI dogfooding

1. In the installed Codex plugin, inspect `memory_setup` with action `status` and `memory_rsi` with action `status`; distinguish configured TypeSafe, active telemetry and backend readiness from verified behavior. For nontrivial work, review a `memory_plan` template and create a scoped durable plan. If tools are missing or storage unavailable, report the limitation instead of inventing persistence.
2. Exercise actual memory retrieval with `memory_ls` → `memory_toc` → `memory_section`, then bounded `memory_search`. Validate generated entries using `memory_validate`; inspect TOC descriptions. Discover each MCP tool's exposed schema before calling it; do not assume this skill defines its parameters. Index only the selected repository with graph-only `gitnexus` analyze, then query a known symbol; never generate embeddings.
3. Distinguish actual installed-plugin behavior from editable-source smoke and adversarial reviewer cases. Record the exact call and observed failure before filing an issue. For a bug, keep a behavioral regression failing before the fix and passing after. Smoke-test changed CLI against representative existing data and long allowed values. Verify search-to-section identity under ambiguous headings, not just output shape. Run relevant full suites once after final integration.
4. `memory_rsi` observe and reflect are local provenance-limited learning; tool-result counts cannot classify failures without arguments. Preflight and audits are advisory, not permission. An invalid TypeSafe response may be transient: retry once and report unavailability rather than asserting a plugin defect. Do not promote policy without source-linked outcomes, counterevidence, paired trials and explicit revision-bound review. Never expose raw private memory, credentials or TypeSafe keys.
5. For an authorized release, open a focused PR, obtain independent review at the exact head, verify CI and merge, then record final evidence and limitations. A reviewer-driven commit makes previous approval stale. Avoid repeatedly checking pending CI; wait once when blocked or do other work and inspect final status. Check CLI-supported JSON fields before querying and prepare the project's test environment before suites. Separate intentional failing-before proof from avoidable errors; refresh edit anchors after file changes.
6. Source merge does not upgrade the installed plugin. Distinguish editable-CLI smoke from upgraded installed-runtime smoke; verify the selected Codex plugin revision and entrypoint. Do not modify an unrelated live agent process merely to demonstrate a patch, and never store TypeSafe keys in plugin settings.
