# Security and identity transitions

Identify actor, protected resource, authoritative policy and physical commit or publish boundary. A callback check before commit can race with denial; a consent timer can expire before activation; logout can leave an old mutation able to write into a new session. Bind asynchronous work to originating identity and generation. Treat repository-local settings and proxy headers as lower authority than operator/user privacy choices.

Prove both directions: adverse ordering and forbidden operation rejected, then legitimate retry/recovery remains usable. A strict handle rejection that strands a real browser is incomplete. Confirm deletion from a previously stored private value, not only an initially empty fixture. Do not treat an external callback as server-confirmed payment or technical green as authority for legal recipient/policy changes.

Diagnostics, browser captures and public review text can expose secrets. Extract only the needed field; prepare outward payloads separately from internal records. Keep authorization source and unresolved owner explicit. A merged dormant change is not activated privacy protection.
