# Codex RSI memory workflow

Decide whether the work is durable: a lasting artifact, multistep implementation, consequential decision or reusable lesson. Quick chat and transient checks need no plan. Use the installed plugin's MCP tools by the names below; inspect their exposed schemas before passing arguments. If a tool or storage is unavailable, name the gap rather than inventing state.

1. For durable work, call `memory_setup` with action `status`. Use `memory_plan` to list templates, review the selected template and pin its revision before creating a plan. For resumed/delegated work, read the existing plan and its latest revision. If the human trusted the Codex RSI hooks with `/hooks`, the SessionStart hook gives a session capability; pass it as `session_token` for `memory_plan` bind/unbind and session-scoped `memory_rsi` observe/clear_signals. Otherwise pass an explicit `plan_id` on read/update, never fabricate a binding. Pass plan ID, revision, pinned template and scoped work items to collaborators. Record decisions, corrections and reviewed outcomes with revision-checked updates. Do not silently weaken pinned requirements; record a scope change through a successor plan when warranted. A plan is evidence tracking, never permission to merge or deploy. Installation, initialization or migration requires explicit selection and review; a status check does not authorize it.
2. Discover existing knowledge with `memory_ls`, then `memory_toc` and `memory_section` for a chosen entry. Use `memory_search` for bounded semantic retrieval and `memory_grep` for exact strings; do not claim a negative search without checking scope or a positive control. When recording a focused reusable lesson, use `memory_new` or `memory_update`, then `memory_validate` and `memory_sync` where configured and authorized. Use `memory_plan` rather than a generic entry for task contracts; don't copy raw private memory into shared artifacts.
3. With `memory_policy`, inspect the current revision/history before proposing a change. Actor labels, assessment scores and green tests are not human approval. Review exact diff and counterevidence; require explicit revision-bound updates. Policy supplements platform instructions and permissions, never overrides them. Sync only into operator-configured allowlisted instruction files after reviewing the preview and checking target revision; do not overwrite user-authored content or assume updating the store changes a running Codex session. This skill is an on-demand workflow, not a Codex system-prompt injection hook.
4. With `memory_rsi`, treat status, observation, reflection, audit, trial and preflight results as bounded evidence, not authority. TypeSafe requires the human's private key setup in an interactive terminal and never a key in tool arguments; saving the key enables future sessions. For a durable improvement, ground it in explicit local evidence, select outcomes through corpus/mine/reduce, prepare/propose/evaluate, and run paired holdout trials before explicit revision-bound promotion. Never automatically send private memory, credentials or prompt material to remote services. Codex hooks can observe bounded tool results after human trust, but do not expose a complete effective system/developer prompt or active skill catalog. Audit only exact available permitted source bodies; report missing instruction layers. Do not infer full review from a selected-file audit. No automatic application or publication follows an assessment.
5. Use `gitnexus` as a graph-only helper for an explicitly selected project: analyze, query a known symbol, then context/impact where useful. Do not generate embeddings, enable semantic fallback or overwrite instruction files. Report the indexed revision and limits instead of treating installed tooling as proof the project is indexed.

For an explicitly requested import, use `memory_setup` migration preview for the selected Markdown sources; inspect the proposed copy, preserve originals and require approval and the expected revision before applying it. Never import credentials or session history.
