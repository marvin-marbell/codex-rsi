# Codex RSI memory workflow

Use the available memory tools when they help the task. Follow the user's current instructions and keep the requested outcome distinct from reusable process guidance. A plan can make longer or delegated work easier to resume, but creating one is not a prerequisite for beginning authorized work. Record a user's correction in the current plan when useful and act on it; do not turn it into an added review gate or silently narrow the requested result.

`memory_plan` lists and reads templates, creates and updates plans, and records steering through `steer` with the current revision. A genuine change to the requested outcome should remain traceable to the user's instruction. A process requirement may be revised or exempted through the supported path without erasing the original task or changing higher-priority instructions. Share relevant context with collaborators, using the same plan only when it helps coordination.

`memory_search`, `memory_toc`, `memory_section` and `memory_grep` retrieve prior knowledge. Save a durable lesson when it can help future work: what failed, what fixed it and when that fix applies. Ordinary acknowledgements and receipt counts belong in task history. Do not promote a stale memory as a live rule after the rule has been revised or retired.

`memory_policy` reads and edits the canonical policy with an expected revision and history. Add, revise, relax and retire ordinary process rules through the same authorized path; preserve user requirements, higher-priority instructions and security boundaries. Review changes in proportion to their impact. Sync only to operator-configured instruction files and preserve unmanaged content.

`memory_rsi` can prepare, propose and promote a revision-bound policy change with source provenance. An evaluation or paired trial is useful when the decision warrants it, but is not a mandatory step for an ordinary authorized edit. TypeSafe assessment remains opt-in; do not send private memory, prompts or credentials to a remote service without the configured disclosure authorization. Codex's trusted hooks may provide local session-scoped signals; without a hook capability use an explicit plan ID. Do not claim a complete prompt or skill audit from unavailable host data.

Use graph tools and validation when they help the requested work. Preserve available evidence and report actual limits; do not manufacture proof or infer that a test or model score grants authority.
